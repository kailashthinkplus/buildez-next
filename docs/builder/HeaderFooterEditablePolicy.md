# Header/Footer Editable Policy

Date: 2026-07-09  
Status: BSP-12 scaffolded policy  
Release Gate: Not passed

## Decision

Header and footer must become editable native Builder structures before they can be generated by AI, inserted by Mapper, or trusted as publish-ready global sections.

The Builder must not persist header/footer as opaque blobs of HTML, React, CSS, or provider output. Global sections must be represented as native Builder nodes with normal selection, inspector editing, serialization, preview, publish, undo/redo, accessibility, and AI compatibility rules.

## Model

Header and footer are site-shared global sections.

Required future model:

- Native Builder section/container/column/widget tree.
- Shared section identity owned at site level.
- Page-level inclusion references the shared section.
- Page-level override policy must be explicit before implementation.
- Preview and publish must consume the same normalized native model.
- AI generation cannot emit global sections until native editability exists.

## Ownership

Global section ownership belongs to the site, not an individual page canvas. A page may include or hide the shared header/footer, but editing the global structure must update the shared site section unless a future page-override system is explicitly introduced.

## Publish And Preview

Preview and publish must render header/footer from the same native Builder global section contract. No separate preview-only, publish-only, runtime-only, or theme-frame-only representation may become the source of truth.

## AI Constraints

AI generation remains blocked for header/footer until:

- Native global section nodes exist.
- Global section serialization is stable.
- Global section history/undo is stable.
- Preview and publish parity is proven.
- Inspector binding is proven for global section controls.
- AI compatibility for global section edits is 90+.

## BSP-12 Scaffold

BSP-12 adds policy metadata in `apps/web-app/modules/builder-v2/theme/globalSectionPolicy.ts`.

Current policy:

- Header AI generation: blocked.
- Footer AI generation: blocked.
- Opaque header markup: blocked.
- Opaque footer markup: blocked.
- Required model: native Builder structure.

This is a safety scaffold, not full editable header/footer implementation.
