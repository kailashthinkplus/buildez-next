# Creative Provider Abstraction

## Purpose

Creative Provider Abstraction lets BuildEZ route bounded creative tasks to replaceable providers without making any provider the source of strategy.

## Provider Rule

Providers execute. BuildEZ decides.

No provider decides:

- business strategy
- brand positioning
- content truth
- website archetype
- `WebsiteSpec`
- component selection
- final page structure
- Builder node model
- compliance claims

## Providers

Potential adapters include:

- Higgsfield MCP
- GSAP
- Framer Motion
- Three.js
- Spline
- Rive
- Lottie
- internal media tools
- future image/video/motion providers

## Contracts

Provider requests must include:

- task type
- creative profile reference
- media or motion strategy reference
- input assets
- truth constraints
- brand constraints
- editability target
- output format expectations
- fallback policy

Provider results must include:

- provider id
- artifact references
- rights/provenance metadata
- warnings/errors
- editability notes
- conversion-to-native-builder requirements

## Multi-Industry Examples

- Real estate: request cinematic gallery concept for provided project images.
- Healthcare: request subtle icon motion, not patient claims.
- Restaurant: request short ambience video treatment for provided footage.
- Automotive: request controlled 3D/service visualization idea.
- Education: request admissions journey diagram styling.
- Hospitality: request destination parallax concept.
- Interior design: request portfolio transition concept.
- D2C: request product spin or detail motion concept.
