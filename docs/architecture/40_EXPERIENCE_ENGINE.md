# Experience Engine

## Purpose

The Experience Engine defines journey and rhythm before composition and component selection.

## Responsibilities

It answers where excitement peaks, where trust is established, when CTA appears, when proof appears, how dense each section should be, where visual breaks happen, what the scroll narrative is, how mobile journey works, where objection handling appears, and where final CTA belongs.

It models journey stages, attention curve, trust curve, CTA cadence, proof placement, content density curve, media rhythm, interaction rhythm, scroll narrative, mobile journey, and conversion friction points.

## Inputs

Business intelligence, brand intelligence, content strategy, conversion goals, device assumptions, accessibility constraints, and repository experience patterns.

## Output

`ExperienceStrategy`.

## Multi-Industry Examples

- Real estate: excitement peaks in hero/gallery, trust builds through location/proof, objections appear before site-visit CTA.
- Healthcare: trust peaks before appointment CTA, dense credentials need calm rhythm and clear mobile action.
- Restaurant: appetite and ambience peak early, menu follows, location and reservation remain reachable.
- Automotive: inventory exploration peaks mid-page, proof and finance support conversion, service/test-drive CTA recurs.
- Education: aspiration opens, programs and outcomes build trust, admissions timeline reduces friction before enquiry.

## Failure Modes

- Treating composition as only section order.
- Placing CTA before the user has enough trust.
- Creating monotonous card grids with no attention or density curve.

## Implementation Guidance

Experience output should feed Pattern Intelligence, Reasoning, Decision Engine, Compiler, Simulation, and Critic. It should be traceable because journey failures are often subtle.
